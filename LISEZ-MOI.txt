STADES 3M – version 4.14.1 (20/11/2026) – ensemble des fichiers

site/                 À déposer à la racine du dépôt GitHub Pages : index.html, config.js, app.js, style.css, icônes,
                      dossier lib/ (bibliothèques), dossier notices/ (les cinq notices d'utilisation) et dossier consultation/
                      (consulter.html : visionneuse hors ligne des copies ZIP, à enregistrer aussi sur votre ordinateur).
                      Version 4.9.0 et suivantes : la copie consultable peut être cumulative (fusion avec la copie précédente, sans doublon).
                      Aucune migration SQL n'est nécessaire pour cette version.
                      Renseignez dans config.js l'adresse et la clé publique de chaque base (production, test).
sql/                  schema_complet_4_7_0.sql      Recrée TOUTE la base depuis zéro (projet Supabase vierge, avec
                                                    pg_cron activé avant l'exécution). Ne sert pas à mettre à jour une base en service.
                      migration_unique_4_4_0.sql    Met à niveau une base (test ou production) jusqu'à la version 4.4.0, avec
                                                    un contrôle de niveau final à comparer entre les deux bases.
                      migration_4_6_0.sql           Étape 4.6.0 : durée en jours, photo de clôture.
                      migration_4_7_0.sql           Étape 4.7.0 : « tribune » devient « zone » (à exécuter puis déposer aussitôt le site).
                      migration_4_11_0.sql          Étape 4.14.1 : catalogue des contrôles de maintenance préventive (à exécuter avant de déposer le site 4.14.1).
                      vidage_base_test.sql          BASE DE TEST UNIQUEMENT : vide les données (confirmation à saisir dans le script).
                      restauration_sauvegarde.sql   BASE DE TEST : remet en place les données à partir d'un fichier de sauvegarde.
fiche_intervention/   Exemples de la fiche d'intervention (PDF et Word) générée par l'application ; non déployé sur le site.
optionnel/            invite-user.ts : fonction d'invitation (non utilisée par l'interface actuelle).

Mise à jour d'une base déjà en service : exécutez, dans l'ordre et une seule fois chacun, les fichiers de migration qui lui
manquent (migration_unique_4_4_0.sql, puis migration_4_6_0.sql, puis migration_4_7_0.sql, puis migration_4_11_0.sql). Chaque script s'arrête avec un message
clair s'il manque une étape précédente et peut être relancé sans risque. Ne relancez plus migration_unique_4_4_0.sql après la
4.6.0 : il recréerait l'ancienne colonne de durée en heures.
Faites toujours une sauvegarde avant (Paramètres > Données > Sauvegarde dans l'application).
